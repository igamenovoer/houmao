# Proposal

## Why

Houmao's claude TUI tracking carries detector assumptions qualified around claude 2.1.81, while the registered interval claims all of `[2.1.0, 2.2.0)`. The 2026-10-12 debug campaign (`context/campaigns/debug/2026-10-12-claude-code-tui-parsing/`) measured the maintained profile against three blind-labeled 5 fps recordings of claude 2.1.296: baseline ready_posture agreement is 0.49 (the profile never asserts `no` while busy), every operator modal reads as idle-ready (843 false-ready samples in the operator-surfaces session), the `Worked for \d+[smh]` completion needle is dead (docks now render `✻ <Verb> for <Nm Ns> · done <time>`), the ghost-cell queued-input structure is dead (queue state now renders as the composer placeholder), and the suffix-less spinner variant escapes the busy regex. The fallback detector scores within 0.04 of the maintained one on every field — it earns nothing. The campaign also produced the repaired detector (monkey-patched candidate, 1.0000/1.0000, 1.0000/1.0000, 1.0000/0.9995 on the two admission booleans with zero false-ready across the three sessions), so the floor cut and the repair land together, mirroring the kimi 2.1.1 and codex 0.162.1 changes.

## What Changes

- **BREAKING**: claude TUI support floor becomes the current latest version, 2.1.296, with an open-ended `>=2.1.296` registration and `qualified_through_version="2.1.296"`. Claude below 2.1.296, or an unparseable claude version, resolves to the explicit `UnsupportedToolVersionError` surface (tool name `claude`) rather than a detector. The claude fallback registration (`FallbackClaudeDetector` and its prompt-behavior variant) is removed; existing deployments running older claude will see an error until they upgrade (migration path: upgrade claude to 2.1.296 or later).
- Promote the campaign's 2.1.296 candidate repairs into the production detector: modal shield first (trust dialog, `Do you want to …` approval panels with `Esc to cancel · Tab to amend`, `Select model` picker — modals force accepting/editing/ready/pending to `no` with activity suppressed); completion marker moves to the `✻`-anchored eight-verb dock set with `Nm Ns` durations, scoped to the latest-turn region instead of full scrollback; busy detection keeps the `esc to interrupt` footer as primary and repairs the spinner regex (optional token suffix, trailing whitespace); queued input moves to the composer placeholder needle `Press up to edit queued messages` (the ghost-cell structure is removed); the interrupt needle widens to `⎿ Interrupted` and `⎿ User rejected` (denial path) on the latest region status line; ready_posture asserts `no` while busy instead of `unknown`; success candidacy is refused while the composer carries a draft; the settle-identity `surface_signature` hashes state-bearing lines only so tip-line/hint churn cannot invalidate a settled success.
- Temporal inference for claude (600 s window): silent Esc abort inference (active → idle with no modal, no interrupt line, and no fresh region dock latches `interrupted` while the aborted prompt restores as a composer draft), slash-menu blink carry (the autocomplete hides busy evidence for a frame while the turn continues), and modal-dismissal restore (a modal opened from an idle interrupted surface restores the interrupted outcome when the `/model` echo re-anchors the region).
- **BREAKING** (shared tracker semantics): a visible composer draft no longer invalidates the latched terminal outcome. The visible-draft invalidation path in the tracker session is removed for claude-driven sessions; outcomes clear on explicit input submission or newer active-turn evidence. Campaign labels hold `last_turn.result` across restored-post-abort drafts and type-phase drafts (`editing_interrupted` / `editing_success` spans), contradicting the current spec scenario that clears on any draft; kimi and codex recorded corpora never exercised the draft-invalidation path, and their qualification gates re-run unchanged as regression evidence.
- Launch floor moves with the tracking floor: `launch_policy/registry/claude.yaml` strategy id `claude-unattended-2.1.81` renamed and `supported_versions` realigned to `>=2.1.296`, with the unattended startup contract re-probed live on 2.1.296 (trust-dialog renders even under `--dangerously-skip-permissions` for untrusted workdirs; auto mode is the 2.1.296 default permission mode and changes the approval-prompt assumptions the 2.1.81 probe was written against).
- Promote the three frozen campaign sessions into `tests/fixtures/shared_tui_tracking/claude/` (first claude corpus) with a qualification replay test mirroring the codex gate (thresholds: session 1 ≥ 0.999, session 2-002 = 1.0, session 2-001 ≥ 0.999 on the two booleans); rewrite stale claude detector/registry unit tests around the 2.1.296 contract.
- Campaign wrap-up: the repair report's Integration Outcome section records this change.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `versioned-tui-signal-profiles`: claude_code profile resolution becomes floor-gated with an explicit unsupported-version error below the floor, no claude fallback registration, and code-side qualified-version metadata; the evidence-backed-profiles requirement extends from Codex 0.162.x / Kimi 2.1.x to Claude 2.1.296 qualified against labeled 2.1.296 recordings; the claude pending-input requirement moves from the ghost-cell structure to the queued-composer placeholder contract.
- `official-tui-state-tracking`: claude detection requirements updated to the 2.1.296 signal contract (modal shield, verb-set dock, footer-primary busy, widened interrupt needle, silent-abort temporal channel, ready assert-no); the newer-turn invalidation requirement loses the visible-draft trigger — drafts no longer clear latched terminal outcomes.
- `claude-cli-noninteractive-startup`: the unattended launch floor realigns from `>=2.1.81` to `>=2.1.296` with the startup contract re-probed against 2.1.296's auto-mode default and always-on trust dialog.
- `shared-tui-tracking-recorded-validation`: recorded-validation target versions move from Claude 2.1.81-era captures to Claude 2.1.296 blind-labeled recordings so the validation spec stops contradicting the floor.

- Tests/fixtures: `tests/unit/shared_tui_tracking/` (registry floor cases, detector tests rewritten), `tests/fixtures/shared_tui_tracking/claude/` (frozen campaign sessions promoted with labels and provenance), qualification replay test added, stale claude detector tests rewritten.

No other runtime behavior change for codex_tui or kimi_code.
