# Design

## Context

See `proposal.md` for motivation and scope. Technically, Houmao's runtime system skills live under `src/houmao/agents/assets/system_skills/` (symlinked at `skillset/runtime/`) and are governed by four runtime modules and one style specification:

1. **Manifest and static pack validators (`src/houmao/agents/system_skill_manifest.py`)**:
   - `manifest.toml` (`schema_version = "houmao-system-skills.v5"`) defines 2 packs (`admin`, `agent`), 6 `[[standalone_skills]]`, 18 `[[shared_routines]]`, and 26 `[[legacy_skills]]`.
   - `EXPECTED_STANDALONE_SKILL_NAMES` hardcodes the exact 6 top-level `SKILL.md` roots. Only `houmao-admin-entrypoint` and `houmao-agent-entrypoint` use `activation = "narrow-implicit"` (`allow_implicit_invocation: true` in `agents/openai.yaml`); the other 4 standalone roots and all 18 shared children use `allow_implicit_invocation: false`.
   - Each of the 18 shared children under `public/houmao-shared-routines/subskills/<name>/` must use `SKILL-MAIN.md` (with no sibling `SKILL.md`), contain `## Actor Frame Gate`, appear as ``| `<route_name>` |`` in `houmao-shared-routines/SKILL.md` alongside a `"When to Route Here"` column, and keep every relative Markdown link inside its own subskill directory (`_validate_local_markdown_links`).
   - `_validate_manifest_operations` requires every declared `commands` and `aliases` entry in `manifest.toml` to appear in the skill's entrypoint or as a `commands/**/<name>.md` stem. `_validate_manifest_object_designators` validates every inline `` `houmao-...->...` `` designator against `manifest.toml`, and `_validate_resource_invocation_notation` requires exact `metadata.skill_invocation_notation` on every entrypoint and designator-bearing Markdown page.
2. **Version synchronization (`src/houmao/agents/system_skill_version.py`, `scripts/check_system_skill_versions.py`)**:
   - All 6 standalone `SKILL.md` files must declare quoted `metadata.houmao_version` matching `pyproject.toml` `[project].version` (`"3.0.0rc8"`).
3. **Legacy migration pinning (`src/houmao/agents/system_skill_lifecycle.py`)**:
   - `[[legacy_skills]]` in `manifest.toml` stores 26 historical v1 SHA-256 `content_digest` snapshot fingerprints (`adbdf84e`) for pre-upgrade copied skill classification alongside `legacy/catalog.v1.toml` (20 entries) and the 6 directories under `legacy/houmao-agent-loop-*` (which `system_skill_lifecycle.py` resolves for symlinked legacy paths), so `houmao-mgr system-skills status|upgrade` can classify pre-upgrade installations.
4. **Unit test assertions (`tests/unit/agents/test_system_skills.py`)**:
   - Asserts exact pack membership, byte-identical staging, `houmao-agent-access` having `access-scope.md` plus `commands/<cmd>.md` for every command, and `houmao-agent-files` having `mount-scope.md` and `receipts.md` plus `commands/<cmd>.md` for every command.
5. **Style guide (`imsight-agent-skill-handling`)**:
   - Requires concise numbered `## Workflow` + native-planning fallback on every entrypoint and executable command page, `Collection-of-routines` vs `Complex-procedure` (`Procedural`/`Helper`/`Misc`) subcommand tables, concise `DO NOT ...` negative guardrails, `"Use when..."` descriptions, and progressive disclosure into `commands/` and `references/`.
6. **Concurrent open change notice (`openspec/changes/revise-agent-permissions-and-mail-filtering/`)**:
   - An unmerged sibling change proposes future breaking permission changes (`agent-observer` retirement, `agent.mail.deliver` removal, recipient mail blocklists). This change (`update-system-skills-post-3-0-0`) targets the **current implemented repository state** (`HEAD` at `3.0.0rc8`); whichever change is applied/archived second must reconcile overlapping deltas in `houmao-agent-access-skill`, `houmao-agent-gateway-skill`, and `houmao-agent-messaging-skill`.

## Goals / Non-Goals

**Goals:**
- Update all 24 existing public skills and `manifest.toml` to cover post-3.0.0 Houmao features accurately and fix all detected contract, link, count, and formatting bugs.
- Apply `imsight-agent-skill-handling` structural and conciseness patterns uniformly without breaking `system_skill_manifest.py`, `system_skill_version.py`, or `test_system_skills.py`.
- Preserve every critical safety gate, actor frame, fail-closed boundary, and task-handling invariant across all skills.
- Keep `legacy/*` and `legacy/catalog.v1.toml` completely unmodified and explicitly documented as frozen migration fixtures.

**Non-Goals:**
- Introducing new standalone skills or new shared subskills, or splitting, merging, or retiring any existing skill.
- Modifying Python runtime validators (`system_skill_manifest.py`) or `legacy/*` skill contents.
- Implementing skill edits during this OpenSpec proposal phase.

## Decisions

### Decision 1: Freeze `legacy/*` and Enforce Zero-New-Skill Boundaries
All 6 directories under `src/houmao/agents/assets/system_skills/legacy/` (`houmao-agent-loop-generic`, `pairwise`, `pairwise-v2`, `pairwise-v3`, `pairwise-v4`, `pairwise-v5`), `legacy/catalog.v1.toml` (20 entries), and all 26 historical v1 `[[legacy_skills]]` SHA-256 `content_digest` entries (`adbdf84e`) in `manifest.toml` remain untouched. `system_skill_lifecycle.py` resolves symlinked legacy paths against `legacy/*` and matches copied legacy installations against the 26 historical `[[legacy_skills]]` digests in `manifest.toml`. New post-3.0.0 loop capabilities live exclusively in `houmao-agent-loop-pro` and `houmao-agent-loop-lite`.

- *Alternative considered*: Updating `legacy/` notes or removing `legacy/` files. Rejected because `system_skill_lifecycle.py` resolves symlinked legacy paths against `legacy/*` and relies on `manifest.toml` `[[legacy_skills]]` digests for upgrade classification, and `R2` forbids retiring or modifying the skill roster topology.

### Decision 2: Deduplicate Cross-Skill Boilerplate Locally Without Cross-Boundary Links
Seven to ten shared subskills currently copy verbatim 7-line `command -v houmao-mgr` launcher blocks, 10-line `Missing Input Questions` blocks, repeated `## Help`/`## Scope`/`## Routing Guidance` lists, obsolete `houmao-cli`/Pixi guardrails, and `"The trigger word houmao is intentional"` disclaimers. Because `system_skill_manifest.py` `_validate_local_markdown_links` rejects any relative link escaping a subskill directory (such as `../../references/...` into `houmao-shared-routines/references/`), shared subskills cannot link to a parent reference file. Instead, each subskill follows the `houmao-agent-access` (61L) and `houmao-agent-files` (68L) pattern: remove the boilerplate from `SKILL-MAIN.md`, replace `Missing Input Questions` with concise workflow steps or skill-specific parameter tables, keep a 1-line `houmao-mgr` invocation rule in `## Workflow` or `references/`, and replace multi-section prose lists with one crisp `## Subcommands` table.

- *Alternative considered*: Centralizing launcher and missing-input boilerplate into `houmao-shared-routines/references/` and linking across subskills. Rejected because `_validate_local_markdown_links` enforces intra-owner containment (`Markdown link ... escapes its owner`), and `skill-layout.md` treats each subskill as its own self-contained resource boundary.

### Decision 3: Progressive-Disclosure Extraction for Monolithic Entrypoints and Bloated Pages
Four shared routines (`houmao-ext-graphing` 282L, `houmao-interop-ag-ui` 262L, `houmao-process-emails-via-gateway` 169L, `houmao-memory-mgr` 142L) currently lack `commands/` and `references/` files and inline all schemas, examples, templates, and procedures in `SKILL-MAIN.md`. During implementation:
- `houmao-ext-graphing`: shrink `SKILL-MAIN.md` to ~85L router, move procedures to `commands/templated-graphics.md` and `commands/freeform-graphics.md` (each with numbered `## Workflow` and fallback), and move schemas/examples/render CLI details to `references/schema-and-render.md`.
- `houmao-interop-ag-ui`: shrink `SKILL-MAIN.md` to ~85L router, move procedures to `commands/{validate,frame,render,publish}.md` (each with `## Workflow`), and move protocol/impl/publish semantics and table examples to `references/protocol-and-impl.md`.
- `houmao-process-emails-via-gateway`: shrink `SKILL-MAIN.md` to ~70L router, move the 17-step round workflow to `commands/process-round.md`, and move reply-hardening rules and the reminder JSON/prompt template to `references/reply-hardening.md`.
- `houmao-memory-mgr`: shrink `SKILL-MAIN.md` to ~80L router, move live read/write/remove and profile memo-seed details into `commands/{read,write,remove}.md` matching `manifest.toml` `commands = ["help", "read", "write", "remove"]`.
- Loop skills (`houmao-agent-loop-pro`, `houmao-agent-loop-lite`): remove `houmao-agent-loop-pro/dev/design/` (1,179 lines of non-runtime maintainer docs), fix all `../reference/` strings to `../../references/`, merge duplicate `## Upfront Planning Rule` into `## Workflow`, and collapse `## Subcommands` + `## Routing` into a single `Complex-procedure` three-split `## Subcommands` table with `Detail` links.

### Decision 4: Synchronize `manifest.toml` (`v5`) and Reconcile Orphaned Command Files
Update `manifest.toml` while preserving `schema_version = "houmao-system-skills.v5"`, the 2 packs, the 6 standalone entries, the 18 shared routine entries, and the 26 legacy digests:
- `houmao-agent-messaging`: set `commands = ["help", "discover", "request", "prompt", "interrupt", "gateway-queue", "send-keys", "mail", "reset-context"]` (adding `"request"` matching `commands/request.md`) and keep `aliases = ["raw-input=send-keys", "mail-handoff=mail"]`.
- `houmao-agent-definition`: retain the 13 `SKILL-MAIN.md` canonical `commands` (`["help", "roles", "recipes", "launch-dossiers", "specialists", "profiles", "recipe-profiles", "definition-authoring", "definition-deployment", "definition-batch", "create-agent-fast-forward", "launch-agent", "stop-agent"]`) so existing `houmao-agent-definition->...()` object designators remain valid, set `aliases = ["presets=recipes", "specialist-mgr=agent-definition", "ready-profile=create-agent-fast-forward", "authoring=definition-authoring", "deployment=definition-deployment", "batch=definition-batch", "launch-instance=launch-agent", "stop-instance=stop-agent"]` to map nested `commands/` file stems cleanly, and remove the 5 unindexed legacy root pages (`create.md`, `get.md`, `list.md`, `remove.md`, `set.md`) plus redundant `low-level/raw-profiles.md`.
- `houmao-adv-usage-pattern`: retain the 5 canonical `SKILL-MAIN.md` `commands` (`["help", "self-notification", "notifier-prompt-driven-mail-loop", "pairwise-edge-loop", "relay-loop"]`) and set `aliases = ["local-close-edge-loop=pairwise-edge-loop", "pairwise edge-loop=pairwise-edge-loop", "pairwise-edge-loop-via-gateway-and-mailbox=pairwise-edge-loop", "relay-loop-via-gateway-and-mailbox=relay-loop", "self-notification-via-reminders=self-notification", "self-wakeup-via-self-mail=self-notification"]`, explicitly accounting for all 6 `commands/*.md` files (`self-notification.md`, mode subpages `self-notification-via-reminders.md` and `self-wakeup-via-self-mail.md`, `notifier-prompt-driven-mail-loop.md`, `pairwise-edge-loop-via-gateway-and-mailbox.md`, `relay-loop-via-gateway-and-mailbox.md`).
- `houmao-mailbox-mgr`: move the 6 distinct command stems (`clear-messages`, `accounts-list`, `accounts-get`, `messages-list`, `messages-get`, `messages-clear`) out of bare `aliases` into `commands`, and add `"agent-binding-online"` backed by new `commands/agent-binding-online.md` for `agents single|self mailbox online {attach|detach|reconnect|refresh|status}`: `commands = ["help", "init", "status", "repair", "cleanup", "clear-messages", "export", "register", "unregister", "accounts-list", "accounts-get", "messages-list", "messages-get", "messages-clear", "agent-binding-status", "agent-binding-register", "agent-binding-unregister", "agent-binding-online"]` and `aliases = ["mailbox-online=agent-binding-online"]`.
- `houmao-project-mgr`: remove the orphaned redirect `commands/launch-profiles.md` (since `houmao-project-mgr-skill` and `houmao-shared-routines-skill` forbid a second executable command for compatibility notes).
- `houmao-agent-email-comms`: keep `commands = ["help", "resolve-live", "status", "list", "peek", "read", "send", "post", "reply", "mark", "move", "archive"]`, add `commands/mark.md` and `commands/move.md` (each with `## Workflow`), and keep `peek` explicitly sharing `commands/read.md` (`[Read or Peek](commands/read.md)`).

## Risks / Trade-offs

- **Broken relative links or undeclared object designators during extraction** → Run `pixi run pytest tests/unit/agents/test_system_skill* tests/unit/srv_ctrl/test_system_skill* tests/unit/docs/test_system_skills_docs.py` and `pixi run check-system-skill-versions` after every batch of skill edits; ensure every file containing `->` carries `metadata.skill_invocation_notation` and every relative link stays inside its owning directory.
- **Test assertions tied to specific files in `test_system_skills.py`** → Preserve `houmao-agent-access/references/access-scope.md`, `houmao-agent-files/references/{mount-scope,receipts}.md`, and `commands/<cmd>.md` files matching `manifest.toml` `commands`.
- **Accidental loss of task-handling edge cases during prose compression** → Each spec delta enumerates the exact critical steps and guardrails that must remain intact, and `tasks.md` mandates an explicit `imsight-agent-skill-handling` conformance and preservation audit.
- **Overlap with `openspec/changes/revise-agent-permissions-and-mail-filtering`** → Reconcile `houmao-agent-access-skill`, `houmao-agent-gateway-skill`, and `houmao-agent-messaging-skill` specs when merging or archiving alongside that sibling change.
