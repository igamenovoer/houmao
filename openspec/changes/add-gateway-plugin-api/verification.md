# Gateway Plugin Acceptance Coverage

This inventory maps the 70 scenarios in the current delta specs to concrete automated assertions. `Covered` means the listed test or completed installed qualification checks the described behavior. The final installed run uses the same product wheel hash as the validated distribution.

Related acceptance issue: [Provide a Supported Gateway Plugin API for External Service Integrations (#76)](https://github.com/igamenovoer/houmao/issues/76). This inventory verifies the accepted change scope; it does not expand that scope to an external provider's transport implementation.

## Installed Qualification Evidence

The [sanitized installed qualification record](../../../examples/gateway-plugin/qualification.md) records the final artifact hashes and results. Both process modes passed healthy custom routes, operator access, cursor continuity, actual gateway-process loss, restart without replay, discarded-success-response duplicate retry, isolated failures, sender retry, and no replay. Each mode observed five actual native client invocations; busy dispatch returned 409 and an interrupted native handoff returned 503. Detached mode tested generation replacement, while auxiliary-window mode tested body-window death.

The qualification verified fresh offline installation, independent owners, selected-only imports, no checkout source imports/search paths, zero provider API calls, an isolated tmux namespace, and completed cleanup. Provider-specific network reconnect remains an implementation responsibility; the generic connection-reporting contract has explicit regression coverage. Streaming exceptions after emitted headers also remain the cooperative plugin author's responsibility because an HTTP host cannot retract an already emitted response.
