# Authenticated Gateway Access Qualification

This record maps the remote gateway requirements to checks using fixture-owned agents, signers, certificates, and provider accounts. The reverse proxy and native execution-owner runs exercise separate trust boundaries on one host. [Issue #84](https://github.com/igamenovoer/houmao/issues/84)

| Requirement | Evidence |
| --- | --- |
| Public input has an independent enablement and budget. Success confirms one-way handoff. | A real HTTPS proxy forwarded notification and prompt requests to a live gateway whose deterministic execution adapter confirmed dispatch. HTTP and runtime tests cover disabled input, readiness, payload bounds, provenance, and uncertain handoff. [HTTPS integration](../../../tests/integration/agents/realm_controller/test_gateway_https_access.py), [gateway HTTP tests](../../../tests/unit/agents/realm_controller/test_gateway_access_http.py) |
| Private operations require current self or verified admin proof. | The HTTPS integration used an enrolled admin and ran the maintained `houmao-mgr agents self mail status` command against the live gateway. A separate Linux operator and owner ran an unattended Codex fixture with an explicit controlled Responses endpoint, owner-only seed and attach inputs, and a stale self key refused after relaunch. [Execution-owner integration](../../../tests/integration/execution/test_codex_owner.py) |
| Admin operations open with an empty list and require a listed key after enrollment. | The HTTPS fixture verified empty-list control, first enrollment, two admins, revocation, and restored open access after final removal. Unit tests cover concurrent registration, replay, stale revisions, and missing or unsafe retained state. [HTTPS integration](../../../tests/integration/agents/realm_controller/test_gateway_https_access.py), [proof tests](../../../tests/unit/gateway/test_access.py) |
| Transport verifies the advertised endpoint and preserves reverse-proxy prefixes. | The HTTPS fixture used generated certificate trust, exercised a prefixed URL, and refused an untrusted certificate. The client tests verify redirect refusal and exact binding. The execution fixtures isolate tmux sockets from the developer's sessions. [Client tests](../../../tests/unit/agents/realm_controller/test_gateway_client.py), [HTTPS integration](../../../tests/integration/agents/realm_controller/test_gateway_https_access.py) |
| Passive and AG-UI paths preserve the same caller authority. | Passive tests cover retained lookup after detach, exact translated relays, and separate owner-service grants. AG-UI stream tests cover first enrollment and lost grant or target. [Passive admission tests](../../../tests/unit/passive_server/test_auth_admission.py), [AG-UI tests](../../../tests/unit/ag_ui/test_connection_routes.py) |
| Remote mailbox access keeps proof, channel, and binding checks in force. | The real offline registry and disposable Stalwart 0.15.5 each passed through verified path-prefixed HTTPS with both foreground and detached gateways. The offline run checked owner-file attachments and stale binding refusal. The online run used generated normal accounts for delivery, reply, read, and archive, and exercised binding attach, refresh, reconnect, and detach. The selected provider binary passed its published SHA-256 check. [Remote mail tests](../../../tests/integration/mailbox/test_authenticated_gateway_mail.py), [Stalwart release assets](https://github.com/stalwartlabs/stalwart/releases/expanded_assets/v0.15.5) |
| Independent plugins respect private and admin admission. | Installed Houmao, the notification example, and CCCC ran outside the checkout in detached and auxiliary-window gateway modes. The CCCC run used a real pinned provider and checked signed ordinary chat and deferred Mail, open and key-required controls, and worker dispatch on a validated broader listener. [Example wheel suite](../../../tests/integration/agents/realm_controller/test_gateway_plugin_packages.py), [CCCC wheel suite](../../../tests/integration/cccc/test_installed_distribution.py) |

The installed and HTTPS runs used loopback provider and proxy connections. The separate-user run used temporary Linux accounts and an explicit socket. A deployment spanning physical hosts and a container-to-host network deployment remain unconfigured in this environment. [Gateway Access and Remote Deployment](operations/access.md)
