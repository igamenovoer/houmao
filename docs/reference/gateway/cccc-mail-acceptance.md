Native journal/provider checks, actual-provider HTTP/recovery checks, actual Stalwart coexistence, independent installed-wheel qualification in both gateway modes, and the required two-real-agent Mail smoke passed on 2026-11-15. ## Journal Failure Scope

Native test-build controls interrupt the actual core read implementation immediately after pending-marker persistence, after the synced native read fact, and after cursor publication. Both consumed and empty outcomes are covered; the controls are absent from production builds. Actual HTTP recovery tests first obtain a genuine native `mail.read` decision, then stop the owned process and restore its precise after-fact/before-cursor or after-cursor crash image with that exact decision/fact identity. A fresh actual daemon must recover the original receipt and effective cursor while keeping the following batch pending. These crash-image checks do not claim to have timed an operating-system kill inside the narrow filesystem write window. Separate actual SIGKILL tests verify restart with a committed response treated as lost.

The core tests also race native `consume_unread` against explicit reads under the same existing `read_cursors.json.lock`. Actual HTTP tests race the native Web inbox-read route against the Actor-scoped operation. Provider state retains only decision/receipt metadata; message content remains in CCCC's native ledger. No production test HTTP endpoint or fault environment option was added.
