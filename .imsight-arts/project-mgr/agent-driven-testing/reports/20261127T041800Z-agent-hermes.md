## Usability Issues

1. **Managed Hermes ignores `--prompt-mode unattended` for command approvals (`mail-stalwart-online-round-trip`, `FAIL`)**: `prepare_hermes_home()` in `src/houmao/agents/hermes_configuration.py:108-112` hardcodes `approvals: {mode: manual, single_query_mode: deny, unattended_mode: deny}`. In `hermes_tui`, any benign command matching Hermes's approval detector (such as `python3 -c` for JSON parsing) hangs the turn indefinitely waiting for interactive Ink approval without surfacing a pending-approval status in Houmao control state (`runs-jmap-b` `state.db` messages `[39]`–`[40]`, `hermes-daemon.log`).
2. **ACP client denies `write_file` in `hermes_service` (`service-lifecycle-and-reasoning`, `PASS`)**: On turn 1 (`state.db` message `[11]`), the ACP client rejected Hermes's native `write_file` call even under `--prompt-mode unattended`, forcing Qwen 3.8 to fall back to shell redirection via `terminal`. Denying structured file writes while permitting arbitrary shell writes misleads agents and adds extra tool turns.
3. **Cryptic `extra_forbidden` error with empty `loc: []` on `/v1/mail/online/list` (`mail-stalwart-online-round-trip`, `FAIL`)**: Sending an unsupported body field (`unread_only`) returned `{"detail": [{"type": "extra_forbidden", "loc": []}]}` without naming the rejected field (`runs-jmap-b` `state.db` msg `[18]`), forcing the agent to re-read skill docs and CLI help.
4. **Root-only `--print-json` flag placement on `houmao-mgr` (`mail-stalwart-online-round-trip`, `FAIL`)**: Passing `--print-json` after a subcommand (`houmao-mgr agents self mail list --print-json`) failed with `No such option '--print-json'` (`runs-jmap-b` `state.db` msg `[22]`), even though agents and users naturally attach output-format flags at the end of a command.

## Uncertainty and Open Questions

Note that Hermes's `tools/approval_context.py` handles YAML `mode: "off"` (quoted string, avoiding YAML 1.1 boolean coercion) and `single_query_mode: "approve"` / `unattended_mode: "approve"`.
