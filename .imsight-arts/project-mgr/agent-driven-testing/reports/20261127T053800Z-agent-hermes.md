## Usability Issues

1. **45-second Hermes startup timeout fails whenever fresh-home `uv sync` exceeds ~40 seconds (`service-lifecycle-and-reasoning` & `tui-native-control-and-detachment`, `BLOCKED`)**: Every fresh managed `HERMES_HOME` triggers Hermes v0.23.4's `pm/worker.py` to populate `298 MB` in `$HERMES_HOME/cache/uv` and compile a `174 MB` venv in `$HERMES_HOME/installs/` (`472 MB` per agent). Across 5 consecutive launches (`46.9s`, `75.5s`, `53.6s`, `44.2s`, `47.9s`), this exceeded the hardcoded `45.0s` deadlines in `src/houmao/agents/realm_controller/backends/service_runtime.py:521` and `src/houmao/agents/realm_controller/backends/hermes_native.py:54`.
2. **Opaque timeout diagnostics and orphaned `pm/worker.py` on rollback**: `Error: Native service startup timed out` does not report that Hermes was still running first-boot `uv sync`, and timeout rollback leaves Hermes's `pm/worker.py` / `uv sync` running detached (PPID `1`) until it completes seconds later.
